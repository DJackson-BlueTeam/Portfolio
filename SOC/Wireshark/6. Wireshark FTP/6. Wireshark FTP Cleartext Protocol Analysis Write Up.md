FTP (File Transfer Protocol) 
---
- Designed to transfer files  
-  Using this in an unsecure environment can cause security threats such as:  
1.  MitM attacks: Lack of encryption and strong authentication ([Adversary-in-the-Middle, Technique T1557 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1557/))
	- Plaintext Data Transmission: a standard FTP transmits all data, which includes username, passwords, and file content in cleartext.
		- If data is unencrypted, an attacker that is positioned between the client and server can use packet sniffing tools to read the bits of information passing through the connection.
	- Lack of server Authentication: Unsecure  FTP does not use SSL/TLS certificates to verify the identity of the server. This allows an adversary to perform DNS Poisoning or ARP Spoofing to redirect user's traffic to a malicious server that looks identical. 
	- Packet Interception and Modification: Once an attacker has successfully inserted themselves into the communication path, they can do the following below.
		- Data Tampering: An adversary can intercept a file being downloaded and inject malicious code or "malware" into it before it reaches the user. 
		- Command Injection: The adversary can modify the FTP commands sent by the client. 
	- Session Hijacking: FTP often uses two separate channels: a command channel and a data channel. An adversary can intercept the unencrypted passive "PASV" or PORT  command used to negotiate these connections. By seeing the IP addresses and ports being opened, the adversary can hijack the data stream to steal files or upload their own data. 
	- **MITRE ATT&CK Frameworks:**
		- T1040: Network Sniffing: [Network Sniffing, Technique T1040 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1040/)
			- Adversaries can capture plaintext FTP credentials as they traverse the network. 
			- Adversaries can also Capture actual files contents being transferred over the unencrypted data channel in a unsecure FTP environment

2. Credential stealing and unauthorized access: Lacking of modern defensive features such as rate-limiting, account lockouts or Multi-Factor Authentication. ([Brute Force, Technique T1110 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1110/))
	- Adversaries can use automated scripts to try different common passwords combinations (Brute Force or Dictionary attacks) against the server.
	- Tools that can be used to conduct task automatically are John-The-Ripper and Aircrack-ng (https://www.fortinet.com/resources/cyberglossary/brute-force-attack)
	- Without lockouts the attacker has unlimited attempts to guess a password until they gain access.
	- Exploitation of Anonymous FTP ([Valid Accounts: Default Accounts, Sub-technique T1078.001 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1078/001/))
		- On most legacy FTP servers, they are configured to allow anonymous logins. which allow adversaries to have anonymous usernames and the password is a placeholder email. 
		- Adversaries can scan servers with a port 21 open and attempt to login anonymously
		- If a FTP is misconfigured, this provides immediate unauthorized access to the file system, which allows adversaries to download sensitive data or upload malicious scripts (Web shells)
	- Credential Replay and Reuse ([Valid Accounts, Technique T1078 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1078/))
		- For FTP that does not use secure token or time-sensitive handshakes, captured credentials can allow be reused.
			- Once an adversary sniff a set of credentials, they can log in from their own machine.
			- A single unsecure FTP session can lead to a full-scale compromise of the user's entire digital identity.
	- Session Hijacking: FTP maintains a Control Channel for commands. If the channel is unencrypted, the attacker can perform a TCP session hijacking attack. ([Remote Service Session Hijacking, Technique T1563 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1563/))
		- The adversary monitors an active, authenticated session. They send spoofed packets to the server that desynchronized the legitimate user and allows the attacker to take over the established connection. 
		- The adversary gains the same level of access as the legitimate user without needing to know the password.

3. Phishing: An unsecure FTP enviornment can cause phishing attacks by providing attackers with the infrastructure and information needed to make their scams appear legitimate.
	- Hosting Phishing Landing Pages: When an adversary gains unauthorized access to an unsecure FTP server, they can upload malicious HTML files. ([Compromise Infrastructure: Server, Sub-technique T1584.004 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1584/004/))
		- The adversary can host fake login pages directly on the companies machine.
		- They can send emails containing malicious links; since the domain is legitimate and trusted, emails filters and users are much less likely to flag it as a scam.
	- Trusted Malware Distribution: Adversaries can replace legitimate files on the FTP server with malicious versions or upload new "Trojan" files. ([Phishing: Spearphishing Link, Sub-technique T1566.002 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1566/002/))
		- The adversary can replace common file "Invoice_Template.pdf" or Software_Update.exe with versions containing malware.
		- The phish: the adversary can send a phishing email telling employees or clients to Download the updated version linked to the unsecure open FTP port. Since the link is maliciously on the company server, the target will trust the download.
	- Data Exfiltration for Spear Phishing: Unsecure FTP servers often contains sensitive directories, employee lists or project files. ([Gather Victim Org Information, Technique T1591 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1591/)) ([Gather Victim Identity Information, Technique T1589 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1589/))
		- An adversary can steal internal documents and contact list form the unsecure server.
		- The Phish: The adversary uses the information to craft a highly convince spear phishing (targeting a specific entity) email.
	- Bypassing Email Security: Many Secure Email Gateways (SEGs) are configured to trust internal or known business domains.([User Execution: Malicious Link, Sub-technique T1204.001 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1204/001/))
		- By compromising the FTP server associated with a trusted domain, the adversary ensures their malicious links are hosted on a reputable IP address (a trust worthy IP based on its historical behavior in online activities).
		- The phishing: a email that points to a compromised but clean domain (one that is not yet on the blacklist) have a much higher success rate of reaching the target inbox.
	- Using the server as a "Dead Drop": Adversaries may use an unsecure FTP server as a centralized location to collect stolen data from other phishing campaigns. ([Application Layer Protocol: File Transfer Protocols, Sub-technique T1071.002 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1071/002/))
		- A phishing kit hosted somewhere else is configured to exfiltrate stolen username and passwords from other phishing campaigns.
		- This hides the attacker's trusted location and uses the targets company's infrastructure to facilitate their broader criminal operations.

|- USER:Username|`ftp.request.code == "USER"`|

|**Advanced Usages Examples for Grabbing Low-Hanging Fruits**||
|- Bruteforce Signals: List Failed Login Attempts|`ftp.response.code == 530`|
|- Bruteforce Signals: List Target Username|`(ftp.response.code == 530) && (ftp.request.arg contains "username")`|
|- Password Spray Signal: List Targets For a Static Password|`(ftp.request.command == "PASS") && (ftp.request.arg == "password")`|

1. How many incorrect login attempts are there? 
- To answer this question, let's use the filter `ftp.response.code == 530` to determine the number of failed attempts 
  ![alt text](https://github.com/DJackson-BlueTeam/Portfolio/blob/8243dfe834a26ea8c4af75905567880124579265/SOC/Wireshark/6.%20Wireshark%20FTP/FTP%20Img/77.png)
  
Answer: 737 

2.What is the size of the file accessed by the “ftp” account?
- We can use the filter `ftp.response.code == 213` to filter out the size of the file access 

  ![alt text](https://github.com/DJackson-BlueTeam/Portfolio/blob/8243dfe834a26ea8c4af75905567880124579265/SOC/Wireshark/6.%20Wireshark%20FTP/FTP%20Img/78.png)
  
Answer: 39424 

3. The adversary uploaded a document to the FTP server. What is the filename
- Usually when a file is uploaded, we can filter using the “RETR”, meaning that a file or a document of some sort was retrieved (RETR) from the user (in this case the adversary) and uploaded.  
- `ftp.request.command == RETR`
  ![alt text](https://github.com/DJackson-BlueTeam/Portfolio/blob/8243dfe834a26ea8c4af75905567880124579265/SOC/Wireshark/6.%20Wireshark%20FTP/FTP%20Img/79.png)

Answer: resume.doc 

4. The adversary tried to assign special flags to change the executing permissions of the uploaded file. What is the command used by the adversary?
- We can filter out a command that is used in a linux machine that changes permissions to a file; which is chmod 
    
- `ftp contains "CHMOD"`

    ![alt text](https://github.com/DJackson-BlueTeam/Portfolio/blob/8243dfe834a26ea8c4af75905567880124579265/SOC/Wireshark/6.%20Wireshark%20FTP/FTP%20Img/80.png)

Answer: CHMOD 777
