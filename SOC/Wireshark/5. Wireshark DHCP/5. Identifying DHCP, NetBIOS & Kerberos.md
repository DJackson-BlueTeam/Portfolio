

**Identifying DHCP, NetBIOS & Kerberos** 

- An analyst should know how to identify hosts on the network apart from IP to MAC address match.  
- When investigating a compromise of malware, an analyst should know how to detect them on the network.  
- There are three different protocols that can be used in Host and User identification:  
    
1. Dynamic Host Configuration Protocol (DHCP) traffic
2. NetBIOS traffic 
3. Kerberos traffic  
    
**DHCP (Dynamic Host Configuration Protocol)**
- This is responsible for managing automatic IP addresses and allowing devices to join a network and receive configuration information.  
-  Some common MITRE ATT&CK frameworks associated with DHCP are list below: 
	- T1557.003: Adversary-in-the-middle: DHCP Spoofing ([Adversary-in-the-Middle: DHCP Spoofing, Sub-technique T1557.003 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1557/003/))
			- Tactic: Credential Access, Collection: When a client sends a DHCP request to join a network, the adversary provide a malicious response containing a default gateway, DNS server or other configuration settings. This allows attacker to intercept, inspect, or modify the client's network traffic.
	- T1046: Network Service Discovery (Reconnaissance) ([Mustang Panda, TA416, RedDelta, BRONZE PRESIDENT, STATELY TAURUS, FIREANT, CAMARO DRAGON, EARTH PRETA, HIVE0154, TWILL TYPHOON, TANTALUM, LUMINOUS MOTH, UNC6384, TEMP.Hex, Red Lich, Group G0129 | MITRE ATT&CK®](https://attack.mitre.org/groups/G0129/))
			-Tactic: Discovery: Adversary use DHCP traffic to gather information about the network environment. By monitoring DHCP request and acknowledgment, the adversary can identify the IP address ranges, active host, and the identity of a legitimate DHCP server.

**NetBIOS (NBNS) Analysis** 
- Is responsible for allowing applications on different host to communicate with each other 
-   Some common MITRE ATT&CK frameworks associated with DHCP are list below:
	- T1557.001: Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay ([Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay, Sub-technique T1557.001 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1557/001/))
		- Tactic: Credential Access: Adversaries spoof NetBIOS Name Service responses when a system fails to resolve a hostname (DNS). By providing a malicious response, the adversary tricks the victim into sending authentication hashes to the adversary machine, which can be cracked or relayed to access other networks.
	- T1135: Network Share Discovery ([Network Share Discovery, Technique T1135 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1135/))
		- Tactic: Discovery: NetBIOS is often used to find shared drives and folders. Adversaries look for open SMB (Simple Message Block) shares (also identified as NetBIOS) to find sensitive data or to identify locations for lateral movement and staging within a Network. 
		- Net: is a command that have various utilities that adversaries use to gather system and network information for discovery, moving lateral through SMB/Windows Admin Shares using the "net use" command, and interacting with services. 
			- net1[.]exe is an execution when net[.]exe is running and can be used directly in commands.  ([Net, Software S0039 | MITRE ATT&CK®](https://attack.mitre.org/software/S0039/))

**Kerberos Analysis** 
- This is an authentication service for Microsoft Windows domains. 
- Some common MITRE ATT&CK frameworks associated with DHCP are list below:
	- T1558.003: Steal or Forge Kerberos Tickets: Kerberoasting
		- Tactic: Credential Access ([Steal or Forge Kerberos Tickets: Kerberoasting, Sub-technique T1558.003 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1558/003/)): Adversaries request a service ticket-granting-ticket (TGT) for a target Service Principle Name (SPN) from the Domain Controller. The ticket is encrypted with the hash of the service accounts password. The adversary can then attempt to crack the password hash offline to obtain the cleartext credentials of the service account.
			- Invoke-Kerberoast ([Invoke-Kerberoast - PowerSploit](https://powersploit.readthedocs.io/en/latest/Recon/Invoke-Kerberoast/)): This is a command that request service tickets for kerberoast-able accounts and returns extracted ticket hashes. It uses "'Get-DomainUser" query for user accounts with non-null Service Principle Names and uses "Get-SPNTicket" to request/extract the crack ticket information using JOHN THE RIPPER. 
		- T1550.003 ([Use Alternate Authentication Material: Pass the Ticket, Sub-technique T1550.003 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1550/003/)): Use Alternate Authentication Material: Pass the Ticket
			- Tactic: Lateral Movement: Adversaries may use a stolen Kerberos ticket (TGT or TGS) to authenticate to a remote system without knowing the user password. The ticket is harvested from the Local Security Authority Subsystem Service (LSASS) process memory on a compromised machine.
				- Local Security Authority Subsystem Service (LSASS) ([OS Credential Dumping: LSASS Memory, Sub-technique T1003.001 - Enterprise | MITRE ATT&CK®](https://attack.mitre.org/techniques/T1003/001/)): is a process memory that stores sensitive information such as user credentials, including password hashes and Kerberos tickets. 
				- Tools: Mimkatz ([ParrotSec/mimikatz](https://github.com/ParrotSec/mimikatz)), Pupy ([n1nj4sec/pupy: Pupy is an opensource, cross-platform (Windows, Linux, OSX, Android) C2 and post-exploitation framework written in python and C](https://github.com/n1nj4sec/pupy/)), LaZagne ([AlessandroZ/LaZagne: Credentials recovery project](https://github.com/AlessandroZ/LaZagne?tab=readme-ov-file)), 
				- Credential-Dumping-Cheat-Sheet ([Credential-Dumping-Cheat-Sheet/Credential Dumping Cheat Sheet.pdf at main · manikanta-suru/Credential-Dumping-Cheat-Sheet](https://github.com/manikanta-suru/Credential-Dumping-Cheat-Sheet/blob/main/Credential%20Dumping%20Cheat%20Sheet.pdf))

1. **What is the MAC address of the host “Galaxy A30”?**  
- To find the MAC address of the host “Galaxy A30”, we will need to use a filter that filters out the host.  
- The filter we will use is *dhcp.option.hostname contains “A30”* <--- We are telling Wireshark to look for a hostname that contains A30 and the results we get are shown below:  
    ![[69.png]]
















Answer: 9a:81:41:cb:96:6c 

2. **How many NetBIOS registration requests does the “LIVALJM” workstation have?** 
- We must use the Display Filter Expression to create a filter that isolate Name Registration traffic 
    ![[70.png]] 

	 ![[71.png]]

- This requires two filters  
- The first filter will be *nbns.flags.opcode == 5* <--- tell Wireshark to isolate traffic involving  name registration 
- The second filter will be *nbns.name matches “LIVALJM”* <--- this tells Wireshark to look for the name associated with LIVALJM 
- *nbns.flags.opcode == 5 && nbns.name matches “LIVALJM”* 
    ![[72.png]]

Answer: 16 

3. ***Which host requested the IP address “172.16.13.85”?*** 
- This also requires two filters  
- The first filter is *dhcp.option.dhcp == 3* <--- telling Wireshark to look for request traffic in the network 
- The second filter is *dhcp.option.requested_ip_address == 172.16.13.85* <--- this is filtering traffic that is associated with the IP address 
- *dhcp.option.dhcp == 3 && dhcp.option.requestd_ip_address == 172.16.13.85* 
    ![[73.png]]

Answer: Galaxy-A12 

4. **What is the IP address of the user “u5”? (defang the IP address)** 
- Since we have the username, we can create a Kerberos filter that is associated with the username “u5” 
- We will use the filter *kerberos.CNamestring == u5* <--- filtering traffic that only have a username of “u5” 
    ![[74.png]]
Answer: 10[.]1[.]12[.]2 

5. **What is the hostname of the available host in the Kerberos packets?**
- We can use the same filter but instead of “== u5” we can put “contains “$” ” 
- In a Windows network, the “$” signifies as a host name 
- *kerberos.CNameString contains “$”* 
    ![[75.png]]








































Answer: xp1$
